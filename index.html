Shikigami

Test any app like a human.

A native macOS tool that tests applications the way a person does — it looks at a window, decides where to click, acts with an emulated cursor, and checks that the right thing happened. No selectors, no DOM, no accessibility hooks required.

Download for macOS

macOS 14 or later · Apple Silicon · brings your own model

How it works

  1. 1
    Pick a window

    Choose any application window from the menu bar. Shikigami tests exactly that window — the rest of your Mac is ignored.

  2. 2
    Write or record a test

    Describe a flow in a tiny plain-language .test.shiki file — or just record your clicks and let Shikigami generate one, adding assertions you type or draw a box around.

  3. 3
    Watch it work

    It observes the window, locates each target (OCR first, a vision model when needed), moves an emulated cursor, and acts — your physical mouse never moves.

  4. 4
    Get a verdict

    Every step resolves to passed, failed, uncertain, or blocked — with before/after evidence kept on anything that didn't pass.

🧩

Application-independent

No selectors, no DOM, no accessibility tree required. If a human can see it and click it, Shikigami can test it — native apps, web views, games, anything on screen.

🖐️

Human-like interaction

An emulated cursor types and clicks inside the target window while your real pointer stays put — so you can keep working as a test runs.

✅

Evidence-based verdicts

Each step is verified by watching the UI actually react. An action that delivers but changes nothing is reported as uncertain — never a false pass.

⏺️

Record into tests

Record a flow and Shikigami writes the test for you, with assertions you add as plain text or by dragging a box on the target to capture exactly what should be true.

🧭

Discover tests

Point it at an app and it proposes reviewable tests within a budget you set. You approve before anything runs, and destructive steps always ask first.

🧠

Bring your own model

One-click local UI-TARS setup, or any OpenAI-compatible endpoint — with an optional separate reasoning model. Screenshots are uploaded only after you consent.

Why test like a human?

Traditional automation binds to selectors, DOM nodes, or accessibility identifiers. The moment those shift, the test breaks — even though the app still works perfectly. Shikigami tests the way a person does: it looks at the screen, decides where to act, acts, and confirms the outcome.

That makes one approach work across completely different apps, and it tells the truth. Results are grounded in what actually appeared on screen — OCR and a vision model read the window, deterministic checks run before any model is asked, and evidence is kept when something fails. No green checkmark unless the UI really changed.

Opening it the first time

Shikigami is ad-hoc signed but not notarized. When macOS blocks it, right-click (or Control-click) Shikigami.app and choose Open, then confirm. You only need to do this once.

You can also clear the quarantine attribute from Terminal:

xattr -dr com.apple.quarantine Shikigami.app

Shikigami lives in the menu bar and asks for Screen Recording and Accessibility on first use — both standard macOS prompts. It needs a vision model: open Local Model to download and serve UI-TARS in one click, or point Settings at any OpenAI-compatible endpoint. Setup Status checks that everything is wired before you run.
